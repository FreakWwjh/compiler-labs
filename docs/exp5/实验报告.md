# 实验五：SLR(1) 引导的语义分析框架

**课程名称：** 编译器设计专题实验  
**实验日期：** 2026/05/30  
**实验环境：** openEuler (aarch64), g++ 12.x, C++17

## 一、实验目的

1. 在 SLR(1) 语法分析的基础上，为每个产生式**嵌入语义动作**，实现**语法制导翻译**。
2. 构建**抽象语法树（AST）**，以树形结构表示程序的逻辑层次。
3. 维护**符号表**，记录变量的声明信息（名字、类型），支持重复声明检测和未声明引用检测。
4. 完成**类型检查**：检测赋值语句和算术表达式中的类型不匹配错误。
5. 生成**中间代码（三地址码）**，将高级代码翻译为更接近机器语言的表示形式。
6. 实现**输入衔接**：接收实验二的 Token 流和实验四的 SLR(1) 分析表作为输入。

## 二、实验原理

### 2.1 语法制导翻译（Syntax-Directed Translation）

在语法分析的同时执行语义动作，实现从文法到目标代码的翻译。每个产生式关联一组语义规则，在**规约（Reduce）**时触发执行。

实验说明给出的核心语义规则如下：

| 产生式 | 语义规则 |
|--------|---------|
| `S → id = E` | `S.code = E.code ‖ gen(top.get(id.lexeme) '=' E.addr)` |
| `E → E₁ + E₂` | `E.addr = new Temp(); E.code = E₁.code ‖ E₂.code ‖ gen(E.addr ':=' E₁.addr '+' E₂.addr)` |
| `E → E₁ * E₂` | `E.addr = new Temp(); E.code = E₁.code ‖ E₂.code ‖ gen(E.addr ':=' E₁.addr '*' E₂.addr)` |
| `E → (E₁)` | `E.addr = E₁.addr; E.code = E₁.code` |
| `E → id` | `E.addr = top.get(id.lexeme); E.code = ""` |

### 2.2 属性栈（Attribute Stack）

标准 SLR 分析器维护**状态栈**和**符号栈**。实验五增加**属性栈**，与符号栈同步操作：

- **移进（Shift）**：终结符的 token 值、类型信息压入属性栈。
- **规约（Reduce）**：弹出右部符号的属性值，执行语义动作，计算左部非终结符的新属性值，压栈。

属性值结构定义：

```cpp
struct SemanticValue {
    string token_val;   // 原始词法值，如 "x"
    string addr;        // 地址/临时变量名，如 "t1"
    ValueType vtype;    // 值类型：INT / FLOAT / ERROR
    ASTNode* ast;       // AST 子树指针
    string code;        // 生成的三地址码片段
};
```

### 2.3 符号表（Symbol Table）

采用单作用域映射实现：

```cpp
class SymbolTable {
    map<string, SymbolEntry> table;
public:
    bool insert(string name, string type);  // 插入变量，检测重复声明
    SymbolEntry* lookup(string name);       // 查找变量
};
```

### 2.4 语义动作执行时机

在 SLR 规约（Reduce）时，根据**产生式编号**调用对应语义动作：

| 产生式 | 语义动作说明 |
|--------|-------------|
| `VarDecl → Type ID SEMI` | 将 `(ID, Type)` 插入符号表；构建 `VAR_DECL` AST 节点 |
| `Assign → ID ASG Expr SEMI` | 查符号表确认 ID 已声明；检查 `ID` 与 `Expr` 类型一致；生成赋值三地址码 |
| `Expr → Expr ADD Term` | 检查左右类型一致；新建临时变量 `tN`；生成 `tN = Expr.addr + Term.addr` |
| `Fact → ID` | 查符号表获取类型；若未声明则报错 |

### 2.5 类型检查规则（简化）

- 支持类型：`int`、`float`
- 算术运算：要求操作数类型完全相同（暂不支持隐式类型转换）
- 赋值：要求左右类型完全相同
- 错误传播：子表达式含错误类型时，父表达式标记为 `ERROR`，避免重复报错

## 四、实验步骤

### 4.1 架构设计

程序分为五大部分：
1. **SLR(1) 分析表生成**（复用实验四核心逻辑，支持现场生成或从文件加载）
2. **AST 节点定义与打印**
3. **符号表实现**
4. **语义动作执行器**
5. **SLR 驱动程序**（状态栈 + 属性栈 + 语义动作回调）

### 4.2 文法设计

采用实验说明给出的简化 C-like 子集，共 20 条产生式（含增广产生式）：

```
Prog     → DeclList
DeclList → DeclList Decl | Decl
Decl     → VarDecl | Assign | Print

VarDecl  → Type ID SEMI
Type     → INT | FLOAT

Assign   → ID ASG Expr SEMI
Print    → PRINT Expr SEMI

Expr     → Expr ADD Term | Term
Term     → Term MUL Fact | Fact
Fact     → ID | INT_NUM | FLOAT_NUM | LPAR Expr RPAR
```

该文法经 SLR(1) 分析表构造验证**无冲突**，确认为 SLR(1) 文法。

### 4.3 Token 流输入

为模拟实验二词法分析器的输出，设计文本形式的 Token 文件，格式为 `(TYPE, value)`：

```
(INT, int)
(ID, x)
(SEMI, ;)
(NUM, 5)
(ADD, +)
```

程序运行时在末尾自动追加 `$` 结束符。

### 4.4 关键代码说明

#### 语义动作执行器

```cpp
SemanticValue executeAction(int prod_id, const vector<SemanticValue>& rhs,
                            int token_pos, SymbolTable& symtab);
```

根据产生式编号 `prod_id` 分发到不同处理逻辑。以赋值语句为例：

```cpp
case 10: { // Assign → ID ASG Expr SEMI
    string vname = rhs[0].token_val;
    SymbolEntry* ent = symtab.lookup(vname);
    if (!ent) semanticError(token_pos, "Variable '" + vname + "' not declared");
    else if (ent->type != valueTypeStr(rhs[2].vtype))
        semanticError(token_pos, "Type mismatch ...");
    res.code = rhs[2].code + ent->name + " = " + rhs[2].addr + "\n";
}
```

#### SLR 驱动中的规约处理

```cpp
// 弹出右部符号的属性和状态
vector<SemanticValue> rhs_vals(rhs_len);
for (int i = rhs_len - 1; i >= 0; --i) {
    rhs_vals[i] = attr_st.top(); attr_st.pop();
    sym_st.pop(); state_st.pop();
}

// 执行语义动作
SemanticValue res = executeAction(prod_id, rhs_vals, pos, symtab);

// 查 GOTO 表，压入新状态和新属性
int next_state = goto_table[top_state][p.lhs];
state_st.push(next_state);
sym_st.push(p.lhs);
attr_st.push(res);
```

## 六、结果分析

### 6.1 SLR(1) 分析表

文法经增广后共 20 条产生式，生成 32 个 LR(0) 项目集。经 FOLLOW 集填表后，**无移进-规约或规约-规约冲突**，确认该文法为 SLR(1) 文法。

### 6.2 属性计算正确性

- **继承属性**：本实验主要使用**综合属性**（S-属性文法），通过属性栈自底向上传递。
- **类型传递**：`Type → INT` 将 `vtype=INT` 综合到 `VarDecl`，`Fact → ID` 通过符号表查询综合类型。
- **地址传递**：表达式规约时，`addr` 字段传递变量名或临时变量名，确保三地址码操作数正确。

### 6.3 错误处理

- **重复声明**：`VarDecl` 语义动作中调用 `symtab.insert`，若返回 `false` 则报错。
- **未声明引用**：`Fact → ID` 和 `Assign → ID ASG Expr SEMI` 中调用 `symtab.lookup`，若返回 `nullptr` 则报错。
- **类型不匹配**：赋值和算术运算中显式比较 `vtype`，不一致时报错。
- **错误恢复**：检测到错误后，继续分析（不中止），尽可能报告更多错误。

### 6.4 与实验四的衔接

实验五直接复用实验四的 SLR(1) 分析表构造逻辑，新增内容完全以**插件形式**叠加：
- 状态栈、符号栈不变
- 新增属性栈（与符号栈同高）
- 新增 `executeAction` 回调（规约时调用）

这种设计体现了编译器前端**词法-语法-语义**的分层架构。

## 七、实验总结

本次实验成功实现了 SLR(1) 引导的语义分析框架，完成了以下目标：

1. **属性栈机制**：在移进-规约分析中无缝集成属性计算，状态栈、符号栈、属性栈三者同步操作。
2. **AST 构建**：每个规约动作同步生成 AST 节点，最终形成完整语法树，树形输出清晰反映程序结构。
3. **符号表管理**：支持变量声明、查询和重复检测，为类型检查提供基础。
4. **类型检查**：实现了简化但完整的类型系统，能检测常见语义错误（类型不匹配、未声明变量、重复声明）。
5. **中间代码生成**：生成三地址码，为实验六（完整中间代码生成）做好铺垫。
6. **输入衔接**：成功读取实验二输出的 Token 流（`(TYPE, value)` 格式）和实验四导出的 SLR 分析表文件。

实验过程中遇到的关键问题及解决方案：
- **属性栈同步**：规约时右部符号的弹出顺序与产生式顺序相反，通过反向填充 `rhs_vals` 数组解决。
- **Token 格式兼容**：实验二输出为 `(TYPE, value)` 格式，实验五原生解析并自动映射 `NUM` → `INT_NUM`/`FLOAT_NUM`。
