# 实验五：SLR(1) 引导的语义分析框架

## 一、实验目的

1. 在 SLR(1) 语法分析的基础上，集成语义动作，构建抽象语法树（AST）。
2. 实现符号表管理，支持变量声明、作用域查询和重复声明检测。
3. 完成属性计算与类型检查，报告语义错误（如未声明变量、类型不匹配）。
4. 生成中间代码（三地址码），为实验六的中间代码生成做准备。

## 二、实验原理

### 2.1 语法制导翻译（Syntax-Directed Translation）

在语法分析的同时执行语义动作，实现文法到目标代码的翻译。每个产生式关联一组语义规则，在**规约（Reduce）**时触发执行。

### 2.2 属性栈（Attribute Stack）

标准 SLR 分析器维护状态栈和符号栈。实验五增加**属性栈**，与符号栈同步操作：
- **移进（Shift）**：终结符的 token 值、类型信息压入属性栈。
- **规约（Reduce）**：弹出右部符号的属性值，计算左部非终结符的新属性值，压栈。

属性值结构：
```cpp
struct SemanticValue {
    string token_val;   // 原始词法值
    string addr;        // 地址/临时变量名
    ValueType vtype;    // 值类型（int/float/error）
    ASTNode* ast;       // AST 子树指针
    string code;        // 生成的三地址码片段
};
```

### 2.3 符号表（Symbol Table）

采用**栈式作用域链**实现：
- `enterScope()`：进入新作用域（压入新映射）。
- `exitScope()`：退出当前作用域（弹出）。
- `insert(name, type)`：在当前作用域插入符号，检测重复声明。
- `lookup(name)`：从内层到外层查找符号。

### 2.4 语义动作设计

| 产生式 | 语义动作说明 |
|--------|-------------|
| `VarDecl -> Type ID SEMI` | 将 `(ID, Type)` 插入符号表；构建 `VAR_DECL` AST 节点。 |
| `Assign -> ID ASG Expr SEMI` | 查符号表确认 `ID` 已声明；检查 `ID` 与 `Expr` 类型一致；生成赋值三地址码。 |
| `Expr -> Expr ADD Term` | 检查左右类型一致；新建临时变量 `tN`；生成 `tN = Expr.addr + Term.addr`。 |
| `Fact -> ID` | 查符号表获取类型；若未声明则报错。 |

### 2.5 类型检查规则（简化）

- 支持类型：`int`、`float`
- 算术运算：要求操作数类型完全相同（暂不支持隐式转换）。
- 赋值：要求左右类型完全相同。
- 错误传播：子表达式含错误类型时，父表达式标记为 `ERROR`，避免重复报错。

## 三、实验环境

- 操作系统：openEuler (aarch64)
- 编译器：g++ 12.x
- 标准：C++17
- 构建工具：make

## 四、实验步骤

### 4.1 架构设计

程序分为五大部分：
1. **SLR(1) 分析表生成**（复用实验四核心逻辑）
2. **AST 节点定义与打印**
3. **符号表实现**
4. **语义动作执行器**
5. **SLR 驱动程序**（状态栈 + 属性栈 + 语义动作回调）

### 4.2 文法设计

采用简化但完整的 C-like 子集：
```
Prog -> DeclList
DeclList -> DeclList Decl | Decl
Decl -> VarDecl | Assign | Print
VarDecl -> Type ID SEMI
Type -> INT | FLOAT
Assign -> ID ASG Expr SEMI
Print -> PRINT Expr SEMI
Expr -> Expr ADD Term | Term
Term -> Term MUL Fact | Fact
Fact -> ID | INT_NUM | FLOAT_NUM | LPAR Expr RPAR
```

该文法无二义性，经 SLR(1) 分析表构造验证**无冲突**。

### 4.3 Token 流输入

为模拟词法分析器输出，设计文本形式的 Token 文件：
```
INT int
ID x
SEMI ;
INT_NUM 5
...
```

每行两个字段：`种属 个体值`。程序运行时在末尾自动追加 `$` 结束符。

### 4.4 关键代码说明

#### 语义动作执行器

```cpp
SemanticValue executeAction(int prod_id, const vector<SemanticValue>& rhs,
                            int token_pos, SymbolTable& symtab);
```

根据产生式编号 `prod_id` 分发到不同处理逻辑。以赋值语句为例：

```cpp
case 10: { // Assign -> ID ASG Expr SEMI
    string vname = rhs[0].token_val;
    SymbolEntry* ent = symtab.lookup(vname);
    if (!ent) semanticError(token_pos, "Variable '" + vname + "' not declared");
    else if (ent->type != valueTypeStr(rhs[2].vtype))
        semanticError(token_pos, "Type mismatch ...");
    res.code = rhs[2].code + ent->name + " = " + rhs[2].addr + "\n";
}
```

#### SLR 驱动中的规约处理

```cpp
// 弹出右部符号的属性和状态
vector<SemanticValue> rhs_vals(rhs_len);
for (int i = rhs_len - 1; i >= 0; --i) {
    rhs_vals[i] = attr_st.top(); attr_st.pop();
    sym_st.pop(); state_st.pop();
}

// 执行语义动作
SemanticValue res = executeAction(prod_id, rhs_vals, pos, symtab);

// 查 GOTO 表，压入新状态和新属性
int next_state = goto_table[top_state][p.lhs];
state_st.push(next_state);
sym_st.push(p.lhs);
attr_st.push(res);
```

## 五、实验结果

### 5.1 测试用例 1：正确程序

**输入**：`int x; x = 5; print x;`

**输出**：
- ✅ 无语义错误
- AST：Program -> DeclList -> [VarDecl(x:int), Assign(x=5), Print(x)]
- 符号表：`x : int`
- 中间代码：
  ```
  x = 5
  print x
  ```

### 5.2 测试用例 2：类型不匹配

**输入**：`int a; float b; a = 3.5;`

**输出**：
- ❌ `Token #10: Type mismatch in assignment to 'a': expected int, got float`
- AST 仍完整构建（错误恢复：继续分析）。
- 符号表：`a : int, b : float`

### 5.3 测试用例 3：复杂表达式 + 未声明变量

**输入**：`int a; int b; int c; c = a + b * 2; d = 1;`

**输出**：
- ❌ `Token #21: Variable 'd' not declared`
- ✅ 表达式 `a + b * 2` 的类型检查通过（均为 int）
- AST：正确反映 `+` 和 `*` 的层级关系
- 中间代码：
  ```
  t1 = b * 2
  t2 = a + t1
  c = t2
  ```

### 5.4 测试用例 4：括号表达式

**输入**：`int x; x = (1 + 2) * 3;`

**输出**：
- ✅ 无错误
- AST：`*` 为根节点，左子树为 `+`（1, 2），右子树为 `3`
- 中间代码：
  ```
  t1 = 1 + 2
  t2 = t1 * 3
  x = t2
  ```

## 六、结果分析

### 6.1 SLR(1) 分析表

文法经增广后共 20 条产生式，生成 32 个 LR(0) 项目集。经 FOLLOW 集填表后，**无移进-规约或规约-规约冲突**，确认该文法为 SLR(1) 文法。

### 6.2 属性计算正确性

- **继承属性**：本实验主要使用**综合属性**（S-属性文法），通过属性栈自底向上传递。
- **类型传递**：`Type -> INT` 将 `vtype=INT` 综合到 `VarDecl`，`Fact -> ID` 通过符号表查询综合类型。
- **地址传递**：表达式规约时，`addr` 字段传递变量名或临时变量名，确保三地址码操作数正确。

### 6.3 错误处理

- **重复声明**：`VarDecl` 语义动作中调用 `symtab.insert`，若返回 `false` 则报错。
- **未声明引用**：`Fact -> ID` 和 `Assign -> ID` 中调用 `symtab.lookup`，若返回 `nullptr` 则报错。
- **类型不匹配**：赋值和算术运算中显式比较 `vtype`，不一致时报错。
- **错误恢复**：检测到错误后，继续分析（不中止），尽可能报告更多错误。

### 6.4 与实验四的衔接

实验五直接复用实验四的 SLR(1) 分析表构造逻辑，新增内容完全以**插件形式**叠加：
- 状态栈、符号栈不变
- 新增属性栈（与符号栈同高）
- 新增 `executeAction` 回调（规约时调用）

这种设计体现了编译器前端**词法-语法-语义**的分层架构。

## 七、实验总结

本次实验成功实现了 SLR(1) 引导的语义分析框架，完成了以下目标：

1. **属性栈机制**：在移进-规约分析中无缝集成属性计算。
2. **AST 构建**：每个规约动作同步生成 AST 节点，最终形成完整语法树。
3. **符号表管理**：支持变量声明、查询和重复检测。
4. **类型检查**：实现了简化但完整的类型系统，能检测常见语义错误。
5. **中间代码生成**：生成三地址码，为实验六做好铺垫。

实验过程中遇到的难点及解决方案：
- **属性栈同步**：规约时右部符号的弹出顺序与产生式顺序相反，通过反向填充 `rhs_vals` 数组解决。
- **AST 内存管理**：采用原始指针 + 析构递归释放，后续可改为 `unique_ptr` 避免内存泄漏风险。
- **类型传播**：子表达式出错时，父表达式不应继续报错。通过设置 `vtype = ERROR` 并在检查中跳过实现错误传播抑制。

## 八、选做建议

1. **作用域嵌套**：扩展文法支持 `{ StmtList }` 复合语句，在移进 `LBR` 时 `enterScope`，规约 `Block` 时 `exitScope`。
2. **更多类型**：支持 `void`、数组类型、函数类型。
3. **控制流语句**：扩展 `if`、`while`，生成带标签的三地址码和跳转指令。
4. **可视化**：将 AST 输出为 Graphviz DOT 格式，生成图片。
