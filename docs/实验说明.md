## 三、第二次实验任务

第一次实验内容：以一个较复杂的DFA为例，目标是能够识别某种语言词法单位。

---

### 主要识别以下几类 Token

| Token 类型 | 说明 | 终态 |
|------------|------|------|
| SCO | 分号 `;` | 2 |
| ID | 标识符（字母开头，字母数字） | 8 |
| INT | 整数 | AB |
| FLO | 浮点数（含小数 / 科学计数法） | CD、EF、FG |
| AAS | 赋值号 `=` | 5 |
| ADD | 加号 `+` | 4A（转移）→6 |
| SUB | 减号 `-` | 0→A |
| DOT | 点号 `.` | 0→C |

- **输入**：小段代码
- **输出**：经过DFA解析，获得token流


---

### 具体词法规则

#### 1. 标识符（ID）

- **构成规则**：**必须以字母开头**，后续可跟任意字母或数字。
- **正规式**：`letter (letter | digit)*`
- **示例**：`a`、`b`、`num123`、`testVar`
- **说明**：本实验未区分关键字与标识符，`int`、`float`等均被识别为普通标识符

#### 2. 整型常量（INT）

- **构成规则**：由**纯数字序列**组成。
- **正规式**：`digit+`
- **示例**：`0`、`123`、`999`
- **支持负数形式**：`-123`（由减号后接整型常量构成）

#### 3. 浮点型常量（FLOAT）

本实验支持**三种标准浮点格式**：

- **小数形式**：`digit+ . digit*`，如 `123.45`、`66.`
- **小数点开头形式**：`. digit+`，如 `.45`、`.9`
- **科学计数法形式**：`(digit+ | digit+.digit* | .digit+) (e|E)(+|-)? digit+`，如 `1e-3`、`12.3E+4`
- **正规式**：整合上述三种形式的浮点数正规式
- **示例**：`123.45`、`.66`、`1e-3`、`9.8E7`

#### 4. 界符与运算符

| 符号 | 类型 | 说明 |
|------|------|------|
| `;` | SCO（分号） | 语句结束标记 |
| `=` | ASSIGN（赋值符） | 用于变量赋值 |
| `+` | PLUS（加法运算符） | 不支持`++`、`+=`等复合形式 |
| `-` | MINUS（减法运算符） | 可表示负数或减法运算 |
| `.` | DOT（小数点） | 用于构造浮点数 |

#### 空白符处理

源程序中的**空格、换行符、制表符**仅作为单词分隔符，词法分析器会自动跳过，不生成任何 Token。

#### 不支持的词法单元

本实验为基础教学版词法分析器，**不支持**以下符号与语法：

- **关键字**：`if`、`else`、`while`、`int`、`float`等无特殊识别
- **乘除运算符**：`*`、`/`、`%`
- **比较 / 逻辑运算符**：`>`、`<`、`==`、`&&`、`||`、`!`
- **括号与花括号**：`(`、`)`、`{`、`}`
- **复合运算符**：`++`、`--`、`+=`、`-=`等
- **字符串 / 字符常量**、注释符号

## 三、实验过程

### 词法分析的前缀

NFA存在歧义，需要维护状态集，速度慢，开销大。词法分析要求线性扫描一次遍历，DFA在 **O(n)** 时间内完成，无回溯、占用内存小无开销。程序设计语言的词法规则明确，无二义性，因此天然适合用 DFA 识别。

### 主文法的词法类别列表

```

KEY = {int, float, void, if, else, while, return, input, print}
INT = {int}; FLOAT = {float}; VOID = {void}; IF = {if}; ELSE = {else}
WHILE = {while}; RETURN = {return}; INPUT = {input}; PRINT = {print}
NUM = L([+-]?[0-9]+)
FLO = L([+-]?[0-9]*.[0-9]+ | [+-]?[0-9]+.[0-9]*)
OP = AOP ∪ ROP ∪ BOP ∪ {=, +=, ++}  AOP = {+, -, *, /}
ADD = {+}; SUB = {-}; MUL = {*}; DIV = {/}

```

## 三、实验三任务

### 目标

构建给定文法的 **LR(0) 项目集规范族**（Canonical Collection of LR(0) Items），为后续生成 SLR(1) 分析表提供基础。

### 实验要求

- 输入文法规则，支持扩展巴科斯范式（如 `E → E + T | T`）。
- 需要手动增广文法：添加新的起始产生式 `S' → S`（S 为原文法起始符号）。
- 输出：生成 LR(0) 项目集规范族，计算每个状态的闭包（Closure）和状态转移（Goto）。
- 输出所有项目集，如可以实现规范族的图形化表示（如状态编号和转移关系）。需要考虑是否属于 LR(0) 文法（无移进-归约或归约-归约冲突）。

> 语法分析则以词法分析输出的单词序列为输入，依据语言的语法规则，构建出对应的语法分析表。

> **【辅助说明：实验输出要求】**
> 1. 增广文法及产生式编号
> 2. 所有项目集（I₀, I₁, ... 按顺序）
> 3. 状态转移表/图
> 4. LR(0) 判定结论（是否为 LR(0) 文法，指出冲突状态）

---

### 实验 3 步骤

1. **增广文法**
   - 添加新的起始产生式 `S' → S`，确保文法有唯一接受状态。

2. **生成初始项目集**
   - 从增广文法的初始产生式 `S' → ·S` 开始，构建初始项目集 I₀。

3. **计算闭包（Closure）**
   - 对每个项目集，递归添加所有可达的 LR(0) 项（如 `A → α·Bβ` 需添加 `B → ·γ`）。

4. **计算转移（Goto）**
   - 对每个项目集和文法符号，计算转移后的新项目集。

5. **结果生成**
   - 重复步骤 3-4，直到不再产生新项目集。

### 实验3

构建给定文法的LR(0)项目集规范族（Canonical Collection of LR(0) Items），为后续生成SLR(1)分析表提供基础。

**实验要求**

- 输入文法规则，支持扩展巴科斯范式（如 `E → E + T | T`）。
- 需要手动增广文法：添加新的起始产生式 `S' → S`（S' 为新增起始符号，S 为原文法起始符号）。
- 要求生成 **LR(0) 项目集规范族**：计算每个状态的闭包（Closure）和状态转移（Goto）。
- 输出所有项目集。
- 规范族的图形化表示（如状态编号和转移关系）。
- 需要考虑是否属于 **LR(0) 文法**（无移进-归约或归约-归约冲突）。

---

### 判断是否为LR(0)文法：

每个状态中不能同时存在移进项目（点后是终结符，如 `A → α·aβ`）与归约项目（点在最右端，如 `B → γ·`）的移进-归约冲突，或者多个归约项目的归约-归约冲突。


> **文法**
> ```
> S → aAcB | Bb
> A → c
> B → b
> ```

> ```
> S → aA·cB    移进-归约冲突
> A → ·c
> 
> S → aAc·B    归约-归约冲突
> B → ·b
> ```

当遇到 `c` 时应将其移进分析栈，继续分析后续符号；或者遇到 `c` 时应将 `A → c` 规约；当遇到 `b` 时应将其移进分析栈，规约为第一个产生式或者规约为第二个产生式。

#### 二者区别

两份规则的关系：附录A中的词法是功能更完整、定义更严谨的超集或升级版。

**主要区别：**
- **标识符定义**：附录A中的词法通过 `\KEY` 操作排除了关键字，避免了词法分析冲突，而第一个词法规则没有
- **运算符完整性**：第一个词法规则严重缺失关系运算符（如 `>`、`!=`）、赋值运算符和逻辑运算符，无法描述完整程序。附录A中的词法定义了完整的运算符集
- **请注意数值定义**：规则B的整数定义（`[0-9]*`）可能匹配空字符串

### 主文法（图片OCR）

```
P → Ď Š

Ď → ε | Ď D ;

D → T d | T d[i] | T d (Ă) {Ď Š}

T → int | float | void

Ă → ε | Ă A ;

A → T d | T d [] | T d (T)

Š → S | Š ; S

S → d = E | d [E] = E | if (B) S | if (B) S else S | while (B) S | return E | {Š} | d (Ř) |

E → i | f | d | d [E] | E + E | E * E | (E) | d (Ř)

B → E r E | E

Ř → ε | Ř R ,

R → E | d [] | d ()
```

每个变元都指代一种语法单元:程序P，声明表Ď,声明D，类型T，整数表Ǐ,形参表Ă ，形参A， Ř实参表，实参R，语句表Š ，语句S，表达式表Ě ，表达式E，布尔表达式B。


### 写成可配置的CFG,程序的输入文件

```
Prog -> DeclList
DeclList -> DeclList Decl | Decl
Decl -> VarDecl | FunDecl
VarDecl -> Type ID SEMI | Type ID LBRACK INT_NUM RBRACK SEMI | Type ID ASG Expr SEMI
Type -> INT | FLOAT | VOID
FunDecl -> Type ID LPAR ParamList RPAR CompStmt
ParamList -> ParamList COMMA Param | Param | ε
Param -> Type ID | Type ID LBRACK RBRACK
CompStmt -> LBR StmtList RBR
StmtList -> StmtList Stmt | ε
Stmt -> VarDecl | OtherStmt
OtherStmt -> ExprStmt | CompStmt | IfStmt | LoopStmt | RetStmt | PrintStmt
PrintStmt -> PRINT LPAR Expr RPAR SEMI
ExprStmt -> Expr SEMI | SEMI
IfStmt -> IF LPAR Expr RPAR CompStmt | IF LPAR Expr RPAR CompStmt ELSE CompStmt
LoopStmt -> WHILE LPAR Expr RPAR Stmt
RetStmt -> RETURN Expr SEMI | RETURN SEMI
Expr -> ID ASG Expr | ID LBRACK Expr RBRACK ASG Expr | ID LPAR ArgList RPAR | SimpExpr
SimpExpr -> AddExpr REL_OP AddExpr | AddExpr
AddExpr -> AddExpr ADD Term | Term
Term -> Term MUL Fact | Fact
Fact -> ID | ID LBRACK Expr RBRACK | INT_NUM | FLOAT_NUM | LPAR Expr RPAR
ArgList -> ArgList COMMA Expr | Expr | ε
```

### 实参和形参部分

`A->Td()`:A 代表函数参数列表的声明。可以是普通变量参数：`A -> T d`，可以是数组参数：`A -> T d[]`，也可以是 函数参数：`A -> T d()`

`Ă->ε|ĂA;Ř->ε|ŘR`:**Ǎ 是函数参数列表的声明集**，A 代表函数参数列表中某个参数的声明。

- 参数之间用**分号**隔开，而不是逗号
- 即使是最后一个参数也需要使用分号结尾

```
void func1(int abc; int xyz; int arr[]; int fun2();)
```

**Ř 是函数调用参数集**，R 是函数参数列表中某个参数的调用。
- 参数之间用**逗号**隔开
- 最后一个参数需要逗号

```
int add(int a; int b;) {
    return a + b
}

int calc() {
    int sum;
    sum = add(3, 4,);
    return sum
}
calc()
```

### 示例代码库和词法的解释

- 程序的 `main` 被识别为 ID，不是关键字
- 关键字只有：`int`，`float`，`void`，`if`，`else`，`while`，`return`，`input`，`print`
- 没有 `for`
- 除了分号 `;` 和逗号 `,`，不支持双引号、单引号、`\\` 等其他界符
- 没有注释
- 升级之后的程序支持与或非等操作
- 支持 `{ [ ( , ) ] } ; ，`
- 验收程序可以支持部分示例文法和示例词法，不需要完全一致
