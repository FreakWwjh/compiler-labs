## 一、实验内容总览

| 项目 | 说明 |
|------|------|
| **实验名称** | 语法分析：LR(0) 项目集规范族设计实现 |
| **核心目标** | 编写 C/C++ 程序，自动构建给定文法的 LR(0) 项目集规范族，输出所有项目集、Goto 转移关系，并判定是否为 LR(0) 文法 |

## 二、完整实验内容（代码实现规划）

### 2.1 核心数据结构

```
Symbol          // 文法符号：区分终结符(T) / 非终结符(NT) / 增广起始符
Production      // 产生式：左部(NT) + 右部(vector<Symbol>)
LR0Item         // LR(0) 项目：产生式编号 + dot位置
ItemSet         // 项目集：set<LR0Item>，用规范编号(I₀, I₁...)
Transition      // 转移边：源状态 + 文法符号 + 目标状态
Grammar         // 文法：所有产生式、起始符号、符号表、增广产生式
```

### 2.2 算法模块分解

| 模块 | 函数/方法 | 说明 |
|------|----------|------|
| **文法解析** | `parseGrammar(filename)` | 读取文法文件，支持 `\|` 分隔多产生式，自动编号 |
| **增广文法** | `augment()` | 自动添加 `S' -> S`，确保唯一接受状态 |
| **闭包计算** | `closure(ItemSet)` | 核心算法：若项目集中有 `A→α·Bβ`，递归加入所有 `B→·γ` |
| **转移计算** | `goTo(ItemSet, Symbol)` | 核心算法：对项目集中所有 `A→α·Xβ`，点后移得 `A→αX·β`，再求闭包 |
| **规范族生成** | `buildCanonicalCollection()` | 从 I₀ 出发，BFS/DFS 反复计算 closure 和 goTo，直到无新状态 |
| **冲突检测** | `detectConflicts()` | 检查每个状态：移进-归约冲突 / 归约-归约冲突 |
| **格式化输出** | `printReport()` | 按实验要求输出增广文法、项目集、转移表、冲突结论 |

### 2.3 支持的文法输入格式

文件 `grammar.txt` 示例：
```
E -> E + T | T
T -> T * F | F
F -> ( E ) | id
```

程序自动处理为编号产生式：
```
(0) S' -> E
(1) E -> E + T
(2) E -> T
(3) T -> T * F
(4) T -> F
(5) F -> ( E )
(6) F -> id
```

### 2.4 输出格式规范

```
==================================================
增广文法 (Augmented Grammar)
==================================================
0: S' -> E
1: E -> E + T
...

==================================================
LR(0) 项目集规范族
==================================================
State 0:
  S' -> .E
  E -> .E + T
  ...
Kernel: S' -> .E

State 1:
  F -> id .
Kernel: F -> id .

==================================================
状态转移图 (State Transition Graph)
==================================================

==================================================

==================================================

  [移进] T -> T . * F
  [归约] E -> T .

❌ 文法存在冲突，不是 LR(0) 文法
```

## 三、实验原理

### 3.1 LR(0) 项目
一个产生式右部某位置加上圆点，形如 `A → α·β`，表示分析过程中已看到 α、期望看到 β。

### 3.2 闭包 (Closure)
对项目集 I，若包含 `A → α·Bβ`（B 为非终结符），则将所有 `B → ·γ` 加入 I，递归直到不再变化。

### 3.3 转移 (Goto)
Goto(I, X) = Closure({ A → αX·β | A → α·Xβ ∈ I })。即从 I 中所有点后为 X 的项目，将点后移，再求闭包。

### 3.4 规范族构造算法
从 I₀ = Closure({S' → ·S}) 开始，对每个项目集 I 和每个文法符号 X 计算 Goto(I, X)。若产生新项目集则加入集合，直到无新状态。

### 3.5 LR(0) 文法判定
- **移进项目**：点后为终结符（或结束符 $），应执行移进
- **归约项目**：点在最右端，应执行归约
- 若某状态同时包含移进和归约项目 → **移进-归约冲突**
- 若某状态包含多个归约项目 → **归约-归约冲突**
- 无冲突则为 **LR(0) 文法**

## 五、实验总结

### 5.1 核心收获
1. 从算法层面完整实现了 LR(0) 规范族的自动生成，深入理解了 Closure 和 Goto 的递归/迭代过程。
2. 认识到 LR(0) 文法的局限性：即使是简单的表达式文法也存在移进-归约冲突，必须借助 SLR(1)、LR(1) 等方法解决。
3. 代码层面掌握了用 C++ `set` + 自定义比较器来规范表示项目集，确保状态去重。

### 5.2 关键代码设计
| 设计点 | 说明 |
|--------|------|
| `LR0Item` 用 (prod_id, dot_pos) 二元组表示 | 节省内存、便于 set 比较 |
| `ItemSet` 用 `std::set<LR0Item>` | 天然去重、有序输出 |
| 规范族用 `std::vector<ItemSet>` + 状态编号映射 | 支持 I₀, I₁... 顺序输出 |
| BFS 构建规范族 | 从 I₀ 出发，队列驱动，保证编号有序 |
