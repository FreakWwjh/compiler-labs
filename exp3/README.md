# 实验三：语法分析 LR(0) 项目集规范族设计实现

## 实验目标

编写 C++ 程序，自动构建给定上下文无关文法的 **LR(0) 项目集规范族**（Canonical Collection of LR(0) Items），计算每个状态的闭包（Closure）和状态转移（Goto），并判定该文法是否为 LR(0) 文法。

---

## 核心功能

| 功能模块 | 说明 |
|---------|------|
| **文法解析** | 支持扩展巴科斯范式（`E -> E + T | T`），自动处理多产生式 |
| **增广文法** | 自动添加 `S' -> S`，确保唯一接受状态 |
| **闭包计算** | 递归扩展非终结符产生式，生成完整项目集 |
| **Goto 转移** | 对给定项目集和文法符号，计算转移后的新项目集 |
| **规范族生成** | 从 I₀ 出发，BFS 构建所有项目集直至无新状态 |
| **冲突检测** | 自动识别移进-归约冲突、归约-归约冲突（接受项目除外） |
| **格式化报告** | 输出增广文法、项目集、状态转移图、LR(0) 判定结论 |

---

## 支持的文法格式

文法文件为纯文本，每行一条产生式，使用 `->` 或 `→` 分隔左右部，`|` 分隔多个右部：

```text
# 注释行以 # 开头
E -> E + T | T
T -> T * F | F
F -> ( E ) | id
```

- 符号以空白分隔（支持 `id`、`(`、`)`、`+`、`*` 等）
- 非终结符自动识别：凡出现在产生式左部的符号均为非终结符，其余为终结符

## 算法要点

### 闭包 (Closure)

若项目集中存在 `A -> α·Bβ`（B 为非终结符），则将所有 `B -> ·γ` 加入项目集，递归直至不再变化。

### 转移 (Goto)

```
Goto(I, X) = Closure({ A -> αX·β | A -> α·Xβ ∈ I })
```

### 规范族构造

从 `I₀ = Closure({S' -> ·S})` 开始，对每个项目集和每个文法符号计算 Goto。若产生新项目集则加入，直至无新状态。

### 冲突判定

- **移进-归约冲突**：同一状态中既有点后为终结符的项目，又有点在最右端的项目（接受项目 `S' -> S·` 除外）
- **归约-归约冲突**：同一状态中包含多个不同的归约项目
